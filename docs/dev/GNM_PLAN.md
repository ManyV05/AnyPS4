# Gnm on the Prospero Vulkan stack: integration plan

How the PS4 graphics path (`libSceGnmDriver`, `libSceVideoOut`) gets a real implementation inside AnyPS5. Measured on CUSA02799 (The Witch and the Hundred Knight) with the runtime built by [tools/stub_generator.py](../../tools/stub_generator.py); the port source is the shadPS4 checkout, which already turns Gnm command buffers into Vulkan.

## 1. Where the title stands

With real `libc.prx` and `libkernel.prx` and stubs for everything else, the title runs its allocator, starts its threads and submits its first command buffer. Then the main thread stops: in a 25 second trace with every call logged, `sceGnmSubmitCommandBuffers` runs once, `sceVideoOutRegisterBuffers` and `sceVideoOutSubmitFlip` never run, and only the audio thread keeps spinning (128,000 `sceNgs2SystemRender` calls). The first submission writes a completion label through an `EVENT_WRITE_EOP`/`RELEASE_MEM` packet and the CPU polls that label (the shadPS4 fix for this title, a `WaitRegMem` on a per-frame counter, is the same mechanism). A stub that returns 0 never writes it.

So the first deliverable is not pixels. It is a command processor that executes the PM4 stream far enough to write labels, raise end-of-pipe events and honor flips. Rendering comes after.

## 3. VideoOut: reuse the Prospero module, inject the Orbis entry points

`core/libs/prx/libSceVideoOut` (2,266 lines) already exports 8 of the 14 functions under the NIDs the title wants: `Open`, `Close`, `IsFlipPending`, `SetFlipRate`, `SubmitFlip`, `UnregisterBuffers`, `AddFlipEvent`, `GetResolutionStatus`. Their signatures are the same on both consoles, and `sceVideoOutAddFlipEvent` takes the `KernelEqueue` of the same `libkernel.prx` the title already uses, so flip waits stay consistent.

The six missing functions are the Orbis-only shape of buffer registration plus trivia:

| Orbis function | Prospero counterpart | Divergence |
|---|---|---|
| `sceVideoOutSetBufferAttribute(attr, pixelFormat, tilingMode, aspectRatio, width, height, pitch)` | `sceVideoOutSetBufferAttribute2(attr2, pixelFormat, tilingMode, width, height, option, dccControl, dccClearColor)` | Orbis `BufferAttribute` is 0x28 bytes: `u32 pixel_format, u32 tiling_mode, s32 aspect_ratio, u32 width, u32 height, u32 pitch_in_pixel, u32 option, u32 reserved0, u64 reserved1`. Prospero `VideoOutBufferAttribute2` is 0x50 bytes with `pixel_format` as a `u64` at 0x20, `option` as `u64` at 0x18, plus DCC fields. Pixel format values differ: Orbis `A8R8G8B8_SRGB = 0x80000000`, `A2R10G10B10 = 0x88060000`, `A16R16G16B16_FLOAT = 0xC1060000`, `A8B8G8R8_SRGB = 0x80002200`, Prospero uses 64-bit codes. A conversion table is required. |
| `sceVideoOutRegisterBuffers(handle, startIndex, void* const* addresses, num, const BufferAttribute*)` | `sceVideoOutRegisterBuffers2(handle, setIndex, start, const VideoOutBuffers*, num, const VideoOutBufferAttribute2*, category, option)` | Orbis passes bare addresses; Prospero passes `{data, metadata, reserved[2]}` records and a set index. The adapter builds the records with null metadata (no DCC on Orbis display buffers) and set index 0. |
| `sceVideoOutRegisterStereoBuffers` | none | Return `SCE_VIDEO_OUT_ERROR_INVALID_VALUE`; the title probes it. |
| `sceVideoOutGetDeviceCapabilityInfo(handle, info*)` | none | Fill `{capability = 0}` (no HDR, no VRR). |
| `sceVideoOutModeSetAny_(mode*, size)` | none | Zero the structure, as shadPS4 does. |
| `sceVideoOutConfigureOutputMode_(handle, reserved, mode*, options, size)` | `sceVideoOutConfigureOutput` | Accept and return 0. |

The module depends on `libSceAgcDriver` for the window and presentation: `DisplayWindow.cpp` creates the SDL2 Vulkan window, `Buffer.cpp` validates guest memory through `AgcDriverCheckGuestMemory`, and `VideoOutDriver.cpp` presents through `AgcDriverPresentBuffer(PresentationWindow, DisplayBuffer, gpuReady, context)`. The `DisplayBuffer` carries `{address, pixel_format, width, height, tiling_mode, pitch, metadata, clear color}`, which is enough to describe an Orbis display buffer once the format code is converted.

Decision: do not copy shadPS4's `videoout` module. Build `libSceVideoOut.prx` the way `libc.prx` is built today: the Prospero sources plus a hand-written `libSceVideoOut_orbis.cpp` complement with the six adapters above. The generator needs one addition for this: a per-module override directory (`core/libs/orbis/overrides/<module>.cpp`) whose definitions count as provided, so the generated complement never duplicates them.

Prerequisite: `libSceVideoOut` links `libSceAgcDriver` and `SDL2-static`, so this step needs the full build (`git submodule update --init --recursive`, SDL2, Vulkan-Headers, the shader recompiler) with the WinLibs GCC 15.2 toolchain, not the relinker-only configuration used so far.

## 4. Gnm: port shadPS4's translator as a module, not function by function

Agc is not a translation target. The Prospero driver (`core/libs/prx/libSceAgcDriver`, 27,000 lines of graphics plus 9,000 of execution) decodes RDNA2 registers and recompiles RDNA2 shaders (`core/shader/recompiler`, 57,000 lines, `RdnaDecoder`). Liverpool is GCN2: different register file (`regs_color.h`, `regs_depth.h`, `regs_shader.h` in shadPS4 are the Sea Islands layout), different PM4 opcodes in places, and a GCN shader ISA the Prospero recompiler cannot read. shadPS4 has all of that working and tested against this very title. Porting its translator is the shortest path; translating Gnm to Agc would mean writing a GCN front end that AnyPS5 does not have.

What is reusable from AnyPS5 for the Gnm module is the glue, not the renderer: the SDL2 window and `PresentationWindow` abstraction (`{context, extensions, createSurface(context, VkInstance), getDrawableSize}`), the `libkernel` event queue (`EqueueAddEvent`, `EqueueTriggerEvent`), the direct memory allocator, and the guest write tracking in `libc` (`GuestWriteWatch`). The port therefore owns its own `VkInstance`/`VkDevice` (shadPS4's `vk_instance.cpp`) and presents into the window the VideoOut module creates. Sharing AnyPS5's `VulkanDevice` across two independently scheduled renderers is possible later but is not needed to get frames.

### 4.2 Where it lives

Put the vendored code in `3rdparty/shadps4-gnm/` with its own `CMakeLists.txt`, not under `core/`. The conventions checker (`tools/check_conventions.py`) forbids comments in `core/` C++ and skips `3rdparty/`; shadPS4 code is commented throughout, and keeping it close to upstream makes later merges possible. Only the adapter layer goes to `core/libs/orbis/gnm/`. shadPS4 is GPL-2.0-or-later, AnyPS5 is GPL-2.0-only; the combination is distributable under GPL-2.0.

Output: `add_library(orbis_libSceGnmDriver SHARED ...)` producing `libSceGnmDriver.prx`, copied also as `libSceGnmDriver_padebug.prx`, exported through `nid_patcher` like the other real modules. The HLE functions keep their shadPS4 names, so their NIDs come out right without aliases; `PS4_SYSV_ABI` maps to `__attribute__((sysv_abi))`, the same calling convention `APS5_VABI` denotes.

### 4.3 Seams to cut

Each item names the shadPS4 header the port currently includes and what replaces it.

1. `core/memory.h` (`MemoryManager`): shadPS4 translates guest addresses and tracks mappings. AnyPS5 runs the title natively, so guest addresses are host addresses; `GetDirectMemoryArea`, `IsValidAddress` and the mapping iteration become `VirtualQuery` plus the direct memory bookkeeping `libkernel` already keeps (`DirectMemory/Export.cpp`). The `MemoryManager` singleton shrinks to a 200-line facade.
2. `core/signals.h` and `video_core/page_manager.cpp`: write tracking for the buffer and texture caches. On Windows shadPS4 uses an access-violation handler plus `VirtualProtect`; AnyPS5's `libc` has `GuestWriteWatch` (`MEM_WRITE_WATCH` polling) and `libSceAgcDriver` has its own read guards. First version: the shadPS4 Windows path unchanged, registered through a vectored exception handler inside the DLL; later unify with `GuestWriteWatch`. This is the highest-risk seam.
3. `core/platform.h` (`IrqC`: `GfxEop`, `GfxFlip`, `GpuIdle`, `Compute*` interrupts): a small interrupt controller class with the same `Signal`/`Register` API, implemented in the adapter layer.
4. `core/libraries/kernel/*` (`equeue`, `process`, `time`): `sceGnmAddEqEvent` and the EOP path add events to a `KernelEqueue`; the adapter calls the `EqueueAddEvent_nid_postfix`/`EqueueTriggerEvent_nid_postfix` exports of `libkernel.prx`. `GetSdkVersion`/process parameters come from the `.procpar` block the title already exposes.
5. `core/libraries/videoout/*` (`VideoOutPort`, `BufferAttributeGroup`, flip requests): `Liverpool` calls the VideoOut driver when a flip packet completes. The adapter forwards to `libSceVideoOut.prx` through a dedicated internal export (`OrbisVideoOutFlipFromGpu_nid_no_patch`), which calls the module's `sceVideoOutSubmitFlip` path and the presenter.
6. `frontend/window_sdl.h` (SDL3 `WindowSDL`) in `vk_presenter`/`vk_instance`: replaced by AnyPS5's `PresentationWindow` (`createSurface(context, instance)`, `getDrawableSize`). The SDL2 window stays owned by `libSceVideoOut.prx`, exactly as it is for Agc.
7. `core/emulator_settings.h`, `core/debug_state.h`, `core/devtools/*`, `imgui/*`: compile-time constants and no-op stubs. The ImGui overlay and RenderDoc hooks are stripped.
8. `common/logging` (spdlog): a thin `LOG_*` macro set over `WriteLogLine` from `libc`'s `LogMacros.hpp`, with the same class names so upstream diffs stay small.
9. Shader cache on disk (`common/path_util.h`, `io_file.h`): point at `<exe dir>/shader_cache/<title id>/`; the title id is in `.procpar`'s process name or `param.sfo`.

### 4.4 Phases and exit criteria

**Phase 3.0, headless command processor.** Vendor `gnmdriver.cpp`, `video_core/amdgpu/*`, `common` subset and the seams 1, 3, 4, 7, 8. `Liverpool` runs with `BindRasterizer(nullptr)`: draws and dispatches are skipped, but `WaitRegMem`, `EVENT_WRITE_EOP`, `RELEASE_MEM`, `WRITE_DATA`, `DMA_DATA` (CPU-visible copies), `WAIT_ON_ADDRESS`, timestamps and flip labels execute, and EOP raises `GfxEop` into the title's equeue. Exit criterion: the main thread leaves its first submit, `sceVideoOutRegisterBuffers` and `sceVideoOutSubmitFlip` appear in the trace, and the title loops at its target rate with the audio stubs. This phase builds in the relinker-only configuration with Vulkan-Headers only.

**Phase 3.1, window and flips.** Build `libSceVideoOut.prx` from the Prospero sources with the six Orbis adapters (section 3), under the full build. Vendor `vk_instance`, `vk_platform`, `vk_scheduler`, `vk_swapchain`, `vk_presenter`, `vk_master_semaphore` and the blit host shaders, with seam 6. `PrepareBlankFrame` presents a cleared frame per flip. Exit criterion: a window at the title's resolution, flip events delivered, no GPU hangs over several minutes.

**Phase 3.2, rendering.** Vendor `shader_recompiler`, `renderer_vulkan` (rasterizer, pipeline caches, `liverpool_to_vk`), `texture_cache`, `buffer_cache` and seam 2 in its unmodified Windows form. Exit criterion: the title's loading screen and menu render; compare against shadPS4 on the same machine.

**Phase 3.3, consolidation.** Replace the exception-handler write tracking with `GuestWriteWatch`, move presentation onto AnyPS5's `VulkanDevice` if a single device proves necessary, and bring the shadPS4 fixes recorded for this title (the `WaitRegMem` watchdog and the `GpuIdle` signal that releases `sceGnmAreSubmitsAllowed`) across as regular code.

### 4.4.1 Phase 3.0 status (18 October 2026): headless processor running, title loops and flips

What exists:

- `3rdparty/shadps4-gnm/` holds verbatim copies of shadPS4's `core/libraries/gnmdriver`, `video_core/amdgpu` (`liverpool`, `regs`, `pm4_*`, tiling and register headers), the `common` subset they need, `fmt` and `magic_enum`; `VENDOR.md` lists the files and the upstream commit. `shims/` replaces the headers of seams 1, 3, 4, 5, 7 and 8 (`common/logging/log.h` over `fmt`, `common/debug.h` without Tracy, `core/memory.h` facade, `core/libraries/kernel/equeue.h` over `libkernel.prx`, `videoout/driver.h` headless port, no-op `vk_rasterizer.h`/`vk_presenter.h`, a three-file Boost stand-in). `adapter/` has `Logging.cpp` (`ORBIS_GNM_LOG=trace|debug|info|warning|error|critical|off`), `Runtime.cpp` (debug state, settings, the system reserved block for the tessellation ring, flip labels), `KernelBridge.cpp` (`EqueueInternal` over `EqueueAddEvent_nid_postfix`/`EqueueTriggerEvent_nid_postfix`, `sceKernelGetCompiledSdkVersion` from `.procpar`) and `Module.cpp` (`RegisterLib` from a static initializer). The one change inside vendored code is in `gnmdriver.cpp` `RegisterLib`: under `ANYPS4_HEADLESS` no presenter is created and `Liverpool` gets the headless port.
- `tools/stub_generator.py --vendored libSceGnmDriver_padebug.prx=3rdparty/shadps4-gnm:libSceGnmDriver` emits `extern "C"` forwarders (`<name>_nid_postfix`) for every NID the vendored sources provide, generated from the header declarations, plus logging stubs for the rest; the module is patched with `nid_patcher --preserve-exports` and copied as `libSceGnmDriver.prx` too. 57 of the title's Gnm imports are forwarded, and the forwarders keep the `[HLE]` trace line.
- Flip labels: `sceVideoOutGetBufferLabelAddress` hands out a 16-entry label array inside the module; `sceVideoOutSubmitEopFlip` registers a one-shot `GfxFlip` handler that clears the label of the previously flipped buffer, exactly as `VideoOutDriver::Flip` does, so `sceGnmInsertWaitFlipDone` waits complete without the watchdog. `VideoOutPort::WaitVoLabel` sleeps on the label with a two-second cap.

What the trace shows for CUSA02799 (`ORBIS_HLE_TRACE=1`, `app0/` junction to the title directory next to the executable):

1. Four `sceGnmSubmitCommandBuffers` during initialization, each followed by the EOP that unblocks the main thread; `sceVideoOutRegisterBuffers` and `sceVideoOutSetFlipRate` follow.
2. The title enters its main loop (`sceUserServiceGetEvent`, `scePadReadState` per frame) and the render thread flips through `sceGnmSubmitAndFlipCommandBuffers` -> `sceVideoOutSubmitEopFlip`: 39 frames, each with `sceGnmSubmitDone`, `sceGnmInsertWaitFlipDone`, a dozen `sceGnmSetCsShader` and two or three `sceGnmSetVsShader`/`sceGnmSetPsShader`. This title never calls `sceVideoOutSubmitFlip`; the Gnm submit-and-flip path is its only flip, so the exit criterion is met through `sceVideoOutSubmitEopFlip`.
3. Frame 40 used to crash on `PhyreEngineRenderThread` at ELF `0xbe6352`, later at `0xbd6536` and once on the main thread at `0xc93d99`: three different sites, each dereferencing values that looked like heap pointers read a few bytes off their slot. A hardware watchpoint on the suspected object table (`0x40c9f28`, run without ASLR so the address is fixed at `0x1440d9f28`) never fired, so the table was a symptom. The common factor was timing: every crash came a few hundred trace lines after the sound thread opened `/app0/sound/0000dynamic_ja.dat` and called `sceNgs2ParseWaveformData`, whose stub returned 0 and left the `OrbisNgs2WaveformInfo` output (format, data size, sample counts, block table) uninitialised; the sound code then allocated and copied with garbage sizes and corrupted the heap. `tools/orbis_impl/libSceNgs2.cpp` now implements it (RIFF/WAVE and ATRAC9 config parsing ported from the shadPS4 fork, with the same defaults for unknown containers) together with the other Ngs2 entry points that write outputs (`SystemCreateWithAllocator`, `RackCreateWithAllocator`, `RackGetVoiceHandle`, `VoiceGetState`, `VoiceGetStateFlags`). With that the title runs past three minutes: 559 EOP flips and 645 waveform parses in the 180-second run, no crash.

Stubs that had to behave for the title to get this far, in `tools/stub_generator.py` (`STUB_IMPLEMENTATIONS`, `STUB_RETURNS`) or as hand-written sources in `tools/orbis_impl/<module>.cpp` (`STUB_EXTERNAL`): `sceUserServiceGetInitialUser` and `sceUserServiceGetLoginUserIdList` write user 1, `scePadOpen`/`sceVideoOutOpen` return handle 1, `sceVideoOutGetResolutionStatus` writes 1920x1080, `scePlayGoOpen` writes a handle, `sceUserServiceGetEvent` returns `SCE_USER_SERVICE_ERROR_NO_EVENT` (the title spins forever on 0), `sceSystemServiceReceiveEvent` returns `NO_EVENT`, `sceNpTrophy*` return `SCE_NP_TROPHY_ERROR_NOT_INITIALIZED`.

Two runtime findings outside Gnm:

- The title's shader table (`newShader/*.fx.phyre`) is read from `/app0`; without `app0/` next to the executable the loader returns empty `shared_ptr`s and the title dereferences one at `0x8bd34`. The runtime layout in `USAGE.md` applies to Orbis titles as well.
- `~PSceneBase` joins its worker thread twice (`sub_c47f50`, then `sub_c47fa0` when the started flag is still set). FreeBSD returns `ESRCH` for the second join; AnyPS5 had already freed the thread object and threw `system_error`. `scePthreadJoin` in `core/libs/prx/libkernel/Pthread/src/Thread.cpp` now checks the live-thread registry first and returns `SCE_KERNEL_ERROR_ESRCH`.

Build: `cmake -S . -B C:/Users/manyv/AppData/Local/Temp/aps4 -G Ninja -DANYPS5_RELINKER_ONLY=ON -DANYPS4_LIBS_DIR=<exe dir>/libs` with the WinLibs GCC 15.2 compilers, then `--target orbis_libs`. The short build path matters: the vendored sources exceed `MAX_PATH` in depfiles under a deep directory.

### 4.4.2 Phase 3.2 status (18 October 2026): window, paced flips, audio pipeline

Phase 3.1 as planned (the Prospero `libSceVideoOut` with Vulkan presentation) needs the full build with the SDL2 and Vulkan submodules, which are not checked out in this clone. Instead the three hand-written modules in `tools/orbis_impl/` give the title a window, paced flips, audio output and a keyboard pad without any of that, through the generator's `STUB_EXTERNAL` mechanism:

- `libSceVideoOut.cpp`: `sceVideoOutOpen` creates a Win32 window on its own thread (scaled to fit the screen), `RegisterBuffers` records the display buffers and their attribute (1920x1080, `A8R8G8B8Srgb`, tiled), and every flip is presented with `StretchDIBits` from the buffer memory. Flips are paced to the display rate selected by `sceVideoOutSetFlipRate` (60/30/20 Hz). The module exports `OrbisVideoOutPresent` and `OrbisVideoOutFlipRequested`; the Gnm module resolves them with `GetProcAddress` and calls them from `sceVideoOutSubmitEopFlip` and the `GfxFlip` handler, so EOP flips and direct `sceVideoOutSubmitFlip` share one path. `GetFlipStatus`, `IsFlipPending`, `GetVblankStatus`, `GetResolutionStatus` and `GetDeviceCapabilityInfo` fill the PS4 structures. Tiled buffers are shown as linear until a detiler exists (phase 3.3); headless the content is black because no draw executes. The window title shows the flip count and the measured rate.
- `libSceAudioOut.cpp`: `waveOut` backend. `sceAudioOutOpen` opens a stereo 16-bit device for MAIN and BGM ports (float and 7.1 sources are converted and downmixed), PADSPK and other ports are paced sinks; `sceAudioOutOutput(s)` blocks until a ring slot is free, which is the pacing the title's audio thread relies on. Every ten seconds each port logs its output count and peak amplitude. `OrbisAudioOutOutputParam` is `{s32 handle; void* ptr}`.
- `libScePad.cpp`: `scePadReadState` maps the keyboard (arrows, Z/X/C/V, Enter, Q/E, 1/3, WASD/IJKL) onto `OrbisPadData`, reports one connected controller and fills `scePadGetControllerInformation`.
- `3rdparty/shadps4-ngs2/`: the NGS2 synthesizer of the user's shadPS4 fork (sampler, pan, submixer, mastering, reverb, EQ, ATRAC9 through LibAtrac9) vendored verbatim as `libSceNgs2.prx` with `--vendored libSceNgs2.prx=3rdparty/shadps4-ngs2:libSceNgs2`. The module keeps no public header, so the generator now also derives forwarders from the `PS4_SYSV_ABI` definitions in `.cpp` files (forward-declared in the complement outside the `extern "C"` block, with the defining file's own includes) and a per-module `complement.cmake` hook adds include paths and flags to the forwarder target. `ngs2_custom.h` had two struct definitions that also declared a global of the same name; they are closed with `};` now (see `VENDOR.md`).
- `liverpool.cpp`: memory fills and memory-to-memory `DMA_DATA` transfers execute on the CPU without a rasterizer (`HeadlessDmaData`), since titles wait for those copies.

### 4.4.4 Phase 3.4 status (18 October 2026): the title reaches its title screen; direct presentation; vendored externals

**Loading profile.** Sampling the loader thread (`loadcallback`) during "Now Loading" with real `libc.prx` symbols (resolved against the unpatched module) put 81 % of its time in `Mspace.cpp`'s `Allocate` and the remaining 15 % in libstdc++'s `_Rb_tree_increment`, with zero file I/O over the sampled 15 seconds (`GetProcessIoCounters`): the loader was not reading, it was allocating. `Allocate` walked the size-ordered free set from `lower_bound(needed)` and rejected every chunk whose start did not satisfy the alignment; with an arena of 1.875 GB fragmented into thousands of chunks slightly larger than the request, each aligned allocation scanned them all. ### 4.4.8 Phase 3.8 status (19 October 2026): audio continuity and balance

**Measurement.** `libSceAudioOut.cpp` can dump what the title hands it and what the mixer plays: `ORBIS_AUDIO_DUMP=<dir>` writes `port<n>-type<t>-<ch>ch-f32-<hz>hz.raw` per port and `mix-2ch-s16-48000hz.raw`, `ORBIS_AUDIO_DUMP_START` (seconds after the first output) and `ORBIS_AUDIO_DUMP_SECONDS` (default 20) bound the window. `scratchpad/audio_analyze.py` reports per-channel RMS and peak, non-finite samples, clipped samples, sample-to-sample jumps and zero gaps; `audio_compare.py` aligns the mix against the expected sum of the ports and writes listenable `mix.wav` / `port1.wav`.

**What the title sends.** The BGM and MAIN ports are 8-channel float, but only L and R carry signal: centre, LFE and the four surround channels are exactly zero in every dump, because the vendored NGS2 mixes stereo voices into `dst[0]`/`dst[1]`. A centre/surround matrix therefore changes nothing for this title; the front coefficients set the level. Port 3 (stereo MAIN) is always silent, port 4 is the pad speaker (paced sink).

**The static ("rain").** The mixer was exact: aligning the dumped mix with `0.212 x (port1 + port2)` gave a residual of 0.000 in every second at a constant 32 ms lag. The discontinuities were in the title's own chunks: 1 132 (BGM) and 1 596 (MAIN) sample-to-sample jumps above 0.09 full scale at 256-frame chunk boundaries against 8 and 6 inside chunks, the mean step at a boundary six times the in-chunk mean, and 518 of 1 900 chunks an exact repeat of the previous one. Cause: the fork's `sceNgs2SystemRender` paces each voice by the wall clock and reuses the cached grain when the voice is more than 8 ms ahead; the mixer released outputs in bursts of up to four chunks (one 20 ms block), so the third and fourth render of a burst repeated the grain. Two fixes: `sceAudioOutOutput` now paces the title per chunk like the hardware does (`PreciseSleepUntil` on a per-port slot clock, `Sleep` to within 2 ms then `SwitchToThread`, `timeBeginPeriod(1)`; the slot resets when the title is late by four chunks or the port holds less than one chunk), and the NGS2 reuse window is 64 ms (`3rdparty/shadps4-ngs2/VENDOR.md`). `std::this_thread::sleep_until` could not be used: on this toolchain it sleeps in 15 ms steps and throttled the title to 40 % of real time (4 758 underruns in a minute). Result over the same prologue window: mean boundary step 0.0129 against 0.0130 inside, 9 boundary jumps against 712 content transients, 0 duplicated chunks, 0 underruns, 0 zero gaps; over a seven-minute run to the swamp dialogue 0 underruns, 0 clipped samples, 135 slot resyncs.

**Balance.** The mixer block is 20 ms (960 frames) in a ring of 12 (240 ms) and ports may queue eight chunks (43 ms) ahead. Matrix: front 0.5, centre 0.707, LFE 0.15, back 0.25/0.15, side 0.27/0.12 (centre above front, surrounds attenuated, as requested; only front applies to this title). The BGM port is scaled by `ORBIS_AUDIO_BGM_GAIN` (default 0.7) and MAIN by `ORBIS_AUDIO_MAIN_GAIN` (1.0). The fork's NGS2 floors the music volume at 0.6 whenever the title asks for near silence (the prologue asks for 0.003); the floor is 0.4 now (`ORBIS_NGS2_MUSIC_FLOOR`), which is what kept the soundtrack over the dialogue. ### 4.4.9 Phase 4.0 status (19 October 2026): real save data, launcher, pad mapping

**Save data.** `tools/orbis_impl/libSceSaveData.cpp` replaces the eight stubs CUSA02799 imports (`Initialize`, `Terminate`, `Mount`, `Umount`, `SetParam`, `SaveIcon`, `DirNameSearch`, `Delete`) with a directory-backed implementation. The title never calls `sceSaveDataOpen`/`Read`/`Write`: on the PS4 those are the deprecated memory API, and this title (like most) mounts a directory and uses ordinary file I/O on the mount point. So a mount creates or opens `savedata/<TITLE_ID>/<dirName>/` next to the executable (`ORBIS_SAVEDATA_DIR` overrides the root, `ORBIS_TITLE_ID` the id otherwise read from `app0/sce_sys/param.sfo`), registers `/savedata<slot>` with libc's `AddPathAlias_nid_no_patch` (resolved with `GetProcAddress` from `libc.prx`, the same mechanism the Prospero `libSceSaveData.native` uses) so the title's `fopen("/savedata0/...")` lands in that directory, and the result carries the mount point and `mountStatus` 1 when the directory was created. Metadata lives in `sce_sys/anyps4.param` (the 1328-byte `OrbisSaveDataParam` written by `SetParam`, `mtime` refreshed on every write and at unmount), `sce_sys/anyps4.blocks` (the requested size) and `sce_sys/icon0.png` (`SaveIcon`). `DirNameSearch` lists the directories that carry a param file, filters with the title's wildcard pattern, sorts by name, user param, blocks, mtime or free blocks in either order, and fills `dirNames`, `params` and `infos` up to `dirNamesNum`, with `hitNum` and `setNum` as the SDK defines them. Errors follow the SDK table (`0x809F0001` not initialised, `0003` busy, `0004` not mounted, `0007` exists, `0008` not found, `000C` mount full). `tools/tests/test_savedata.cpp` drives the whole API on a temporary directory (30 checks: create/open/read-only/CREATE2 mounts, BUSY/EXISTS/NOT_FOUND, params, icon, search with sorting, wildcard and block accounting, delete) and passes; it compiles the module with the host ABI because GCC 15.2 crashes on a cross-ABI call from `main`. **Pad.** `libScePad.cpp` reads `pad.ini` (`ORBIS_PAD_CONFIG`, default `anyps4/pad.ini` next to the executable; key names from `tools/orbis_impl/PadKeyNames.hpp`, shared with the launcher) and polls an XInput gamepad in slot 1 (A/B/X/Y to Cross/Circle/Square/Triangle, shoulders, triggers above 30 as L2/R2 with analog values, Start to OPTIONS, Back to the touch pad, thumbs to L3/R3, sticks with a 7849 dead zone), rechecking a disconnected pad every two seconds. ### 4.4.10 Phase 4.1 status (19 October 2026): sound effects, music sequencing, diagnostics

**Instrumentation.** `ORBIS_NGS2_TRACE=1` makes the vendored NGS2 log every voice setup (type, channels, rate, config), every volume, matrix and event call with the voice's rack, bytes, gains, patch destination and position, every state poll, the render buffers of each system and, every 2000 renders, each playing voice with the peak of its grain. `ORBIS_GNM_DUMP_EVERY=<n>` dumps every n-th flip through the readback path. The launcher's "Diagnostics" checkbox sets both plus `ORBIS_GNM_LOG=info`, and every launch now writes `<install>/anyps4/log/session-<date>.log`, so a normal play session produces the data. `scratchpad/ngs2_trace_summary.py` condenses a trace (voices by rack and format, events per rack, volume calls, render probes).

**Sound effects (root cause found).** The trace of the opening shows 571 `unrecognized waveform data` warnings: every sound effect of the title is a raw `VAGp` (HEVAG) file ("footsteps on grass", "monster roar", "sword slash", "fire"), which the fork's `sceNgs2ParseWaveformData` did not parse (only RIFF/WAVE). It answered with a made-up format, 2 channels at 48 kHz and `size/4` samples, so the title set its 256 effect voices up as stereo PCM with wrong durations. The parser now reads the VAG header (big-endian data size at 0x0C and sample rate at 0x10, channel count at 0x1E, 16-byte units of 28 samples) and reports mono 44.1 kHz with the real sample count; the data offset stays 0 so the decoder, which already handled HEVAG when it saw the header, takes rate and channels from it. Effect voices now carry the correct format in `setup voice` lines.

**Music sequencing (root cause found).** The title drives its music from the state of its four mastering voices, which it polls every grain with `sceNgs2VoiceGetState` (76 bytes: flags, limiter levels, input and output peak meters), never from the sampler voices. The fork reported the mastering voices as not PLAYING with meters at either zero or a constant one, and the title reacted by fading every track out within a second of starting it; the fork then kept stopped tracks alive and floored their volume, which is what played the wrong track in the village. The mastering voices now report PLAYING once played, with real meters: the peak of what was mixed into each bus on the last render. Two further pieces: the sampler state also fills `decodedDataSize`, the block `userData` and the waveform pointer, and the music hold is scoped: a track the title fades out within its first three seconds while no other music plays is held at the volume it reached, hidden from the bus meters so the title's sequencing proceeds, and retired the moment another music track plays; a Stop or Kill with another track playing is honoured. `ORBIS_NGS2_MUSIC_HOLD=1` restores the fork's unconditional hold, `ORBIS_NGS2_MUSIC_FAITHFUL=1` disables even the scoped hold. Verified on the opening: the boot track is held, the logo track replaces it and plays 23 s at the title's own volume, the title track replaces that, "New Game" starts the prologue track, and a 25-second dump in the prologue has music with no silent frames. The scoped hold remains a guess about intent: the title may want silence in some scenes, and the faithful switch exists for that comparison.

**Pacing.** The per-chunk slot clock keeps its four-period tolerance. Resynchronising on every late chunk (the "no catch-up" variant) was measured: 11 544 resyncs and 274 underruns in twelve minutes against 135 and 0, because the Windows sleep always overshoots a little and the queue then drains. The dialogue-start hiccup was not reproduced in the dumps taken (no gaps, no duplicated chunks); the trace logging itself costs audio time (resyncs rise with `ORBIS_NGS2_TRACE`), so measurements of the hiccup must be taken without it.

**Village dialogue background.** Not reproduced: the scripted route reaches the self-assertion tutorial and the second name entry but not the village (the dialogue needs stick input and the sequence is not yet scripted), and the title must not be launched while a play session is running. The diagnostics mode exists so that a session that reaches the dialogue leaves its log and periodic frame dumps in `anyps4/log` and `anyps4/screenshots` for the texture-cache investigation.

### 4.4.12 Phase 4.3 status (24 October 2026): fence watchdog, save dialog, NGS2 on the fork's defaults

Reference for this phase: the user's shadPS4 fork (`witch-fixes`, commit `354faa4`), which testers report free of the cut-scene, music and audio-dropout problems seen here. The vendored renderer, texture cache and NGS2 are that fork's code, so the work was to find where AnyPS4 deviates from it and to put the fork's behaviour back as the default. No test runs were made; the user verifies.

**Forced fences (flicker, black lines, torn particles).** Every traced run forced the title's per-frame fence about once per two frames (`Gfx WaitRegMem timeout` logged once per thousand: 131 lines in 136 200 flips, 22 in 43 200). The CP parks on the odd value of the counter at `0x292458008`, which the title's CPU writes after `sceGnmSubmitDone` returns; the fork's watchdog forces it after 100 000 spins (500 000 on the compute ring). A spin here is a `Test` plus a coroutine yield with nothing else to run, so the budget elapses in a few milliseconds, inside a normal CPU frame, and the CP then draws with vertex and texture data the title is still writing. Presentation at 120 to 170 flips per second hid it partly; at the 60 fps cap the CPU has a full 16 ms frame and would trip it every frame. `liverpool.cpp` keeps the spin counts but arms a wall-clock limit with them. A fixed limit of 1000 ms was tried first and ran New Game at one frame per second: in that transition the title's CPU waits for the GPU while the CP waits for the fence, so every wait expires and each costs the full limit. The limit is therefore adaptive (`FenceWatchdog`, one per ring): it halves after every forced fence, down to `ORBIS_GNM_FENCE_TIMEOUT_MIN_MS` (8 ms), so a circular wait costs milliseconds per frame as with the fork's spin budget, and it rises to four times the longest fence the CPU delivered on its own (decaying slowly towards that), capped by `ORBIS_GNM_FENCE_TIMEOUT_MS` (1000 ms), so in play the CP waits for a late CPU the way the hardware does instead of drawing torn data. Forced fences are logged once per hundred with the elapsed time and the current limit, and the `WaitRegMem stats` line carries the forced count and the limit.

**Save data (black screen at the fairy).** The title's save flow is `sceSaveDataDialogOpen` (the slot list or a confirmation), then `Mount`, file writes through the `/savedata0` libc alias, `SetParam`, `SaveIcon`, `Umount`, and again the dialog for the "saving" and "saved" messages. The old dialog stub read the mode from the wrong offset (`param[1]`, inside the 48-byte common-dialog base), answered every dialog after 30 status polls, and never wrote the selected directory name into the result, so a list dialog returned an empty selection and a progress or no-button message was reported finished while the title still owned it. `libSceSaveDataDialog.cpp` now mirrors the fork's `SaveDialogUi`: the parameter block is parsed with its real layout (`static_assert`ed offsets), a list dialog answers with `focusPosDirName` or the first listed directory written into the caller's `dirName` buffer (empty for a brand-new slot, as the fork does), user and system messages answer with the positive button after ten updates, and dialogs without buttons (`NONE` button type, `PROGRESS` system message, progress bar) stay `RUNNING` until the title closes them. Every open, finish and close is logged with mode, type, buttons and selection. In `libSceSaveData.cpp` the module lock now covers only the slot table: directory creation, parameter and icon writes, the directory scan of `DirNameSearch` and `Delete` run with the lock released, as asked. `libc.prx` in both the development and the play install exports `AddPathAlias_nid_no_patch`, so the alias path is in place; the first save with the new build will log `[SaveData] mount ... (created)` followed by the title's file writes.

**NGS2 on the fork's defaults.** Phase 4.1 moved three behaviours away from the fork on the strength of traces of the opening; the village music and dialogue reports say the fork's are the right ones for the whole title, so they are the defaults again, with the 4.1 behaviour behind switches:
- Music hold: `ORBIS_NGS2_MUSIC_HOLD` = `fork` (default: Stop and Kill on a music voice are suppressed and the next music Play retires it; the title's own fade-out one second after a track starts no longer silences it, and entering or leaving a house swaps the track through the new Play), `scoped` (the 4.1 rule) or `off` (`ORBIS_NGS2_MUSIC_FAITHFUL`). The music floor is 0.6 like the fork unless `ORBIS_NGS2_MUSIC_FLOOR` (the launcher slider) sets it; the launcher's saved value of 40 % still applies until the slider is moved.
- Mastering voices report like the fork (never PLAYING, meters zero) unless `ORBIS_NGS2_MASTERING_METERS=1`; the fork found that a bus reporting PLAYING makes the title duck its music permanently.
- The extended sampler state (bytes consumed, block user data, waveform pointer) is filled only with `ORBIS_NGS2_SAMPLER_EXT=1`; the fork leaves it zero, and the title's streaming of dialogue is known to work that way.
- Grain pacing window back to the fork's 8 ms (`ORBIS_NGS2_GRAIN_WINDOW_MS` overrides); the 64 ms window of phase 3.8 is unnecessary now that `sceAudioOutOutput` paces the title per chunk, and it let a voice run two renders ahead at its start.
- `VAGp` parsing stays on (the sample counts and channel layout it reports are the file's); `ORBIS_NGS2_VAG_PARSE=0` reproduces the fork's generic defaults for comparison if sound effects behave differently.
Voice allocation is the title's: it owns 256 sampler voices on one system and sets a voice up (`SamplerSetup`) before each effect; `sceNgs2SystemRender` mixes every playing voice of the system into the one 8-channel buffer the title renders per cycle, one-shots end at the end of their data so the slot reports free at once, and only streaming voices (more than one `AddWaveformBlocks`) survive a 30-render underrun. Nothing in that path limits how many effects play at once.

**AudioOut.** `MixBlock` copies ports that run at the mixer rate (48 kHz, every port this title opens) sample for sample; the linear interpolation is only used for ports at another rate. For 48 kHz ports it was already an identity (the interpolation weight was always zero), so this changes nothing audible; the start-of-dialogue repetition is addressed by the NGS2 defaults above.

**Not changed, and why.** Depth bias or depth range in `vk_rasterizer.cpp`: the renderer applies the title's own `PA_SU_POLY_OFFSET` registers through `vkCmdSetDepthBias`, exactly as the fork, and the black lines reported have the signature of the forced fences, not of z-fighting. Render-target view synchronisation in `texture_cache.cpp` and particle blend state: the vendored files are byte-identical to the fork's; the diagonal cut and the green particle squares are consistent with the GPU reading half-written buffers and should be re-checked after the fence change. The three screenshots mentioned in the request did not arrive.

### 4.4.14 Phase 4.5 (24 October 2026): NGS2 audio telemetry

Three instruments in the vendored NGS2, all on with `ORBIS_NGS2_TRACE=1` (the launcher's Diagnostics box), so that the reported low-pitched voices, one-shot effects that never return and broken music loops can be read from data instead of descriptions:

- **Voice PCM dumps** (`ORBIS_NGS2_DUMP=1` alone also enables them): every decoded source frame of every voice, exactly what the AT9, HEVAG or PCM decoder produced before resampling and mixing, is appended to `<install>/anyps4/audio_dumps/voice-<handle>-<rate>hz-<channels>ch-<codec>-<n>.wav` as 32-bit float WAV (header rewritten every 64 frames and at close; a new file per sampler setup or rate change; at most 256 files and 120 s each). A wrong decode is audible and visible in the file at the rate the decoder believed.
- **Voice lifecycle tracker**: every Play, Stop, StopImm, Kill, Pause and Resume logs `lifecycle <event> voice <h> rack <r> (id): active N / limit M, playing, has_data, pos`, where the limit is the rack's `maxVoices` from its creation option and N counts the rack's voices that are playing or pending; a full rack logs `Voice Leak Detected`. The 2000-render summary also prints every rack's `N / M`.
- **Pitch and sample-rate monitor**: the first grain of every voice setup logs `rates voice <h>: file R Hz C ch (codec), declared R' Hz C' ch, pitch P, step S -> 48000 Hz`, flagging a declared rate that differs from the file's; `step` is the resampling increment actually used.

### 4.4.15 Phase 4.6 (24 October 2026): what the audio telemetry showed, and the fixes

Session `session-20261024-155326.log` (792 688 lines, Diagnostics on) and 256 voice dumps (110 MB).

**Low-pitched voices: a stale decoder kind.** 113 `rates voice` lines read `file 44100 Hz 1 ch (at9), declared 48000 Hz 1 ch, step 0.9187`, although every AT9 mono setup declares 48 kHz, the files' RIFF headers say 48 kHz and the AT9 configuration (`0xf00670fe`) is 48 kHz. The 44.1 kHz came from the VAG branch of `ProduceGrain`: `ResetVoiceDecoder` never cleared `pcm_kind`, `vag_rate` and `vag_channels`, so a voice slot that had played a VAG effect kept `PcmKind::Vag` and its header rate, and the next AT9 line on that slot was resampled with step 0.9187, eight per cent slow and a semitone and a half low. The kind and the VAG values now reset with the decoder, and the VAG branch applies only to non-AT9 formats. The same stale state could decode a VAG file as raw PCM on a slot that had played PCM.

**Effects that stop coming back: a 2 MB effect held as music.** The lifecycle tracker shows no leak (sampler racks peak at 10 of 256 and 1 of 64 voices; the 8-voice rack at `0x...100000` is the BGM rack; every Play of a one-shot ends by itself). But voice `0x4e53000000300070`, a 2 MB AT9 waveform on the 256-voice rack patched to the effects bus, was played 124 times and classified as music by size alone, so its Stop and Kill were suppressed by the music hold (`holding music voice 0x4e53000000300070 through Stop at 7.3s ... through Kill at 16.0s`). Music is now a long waveform on a small rack (`IsMusicWaveform`: over 1 MB and `maxVoices` at most 8), and the Play, Stop and Kill paths all use that classification.

**Music loops.** The loop points are read and used (`music voice ... loops from sample 2535280 to 8668336`, positions in the render probe wrap at the loop end), but the rewind decoded and discarded up to the loop start (two million samples of AT9) in one render call, a stall at every loop. AT9 superframes decode independently, so the sampler now seeks to the superframe that holds the loop start and discards only the remainder.

**Decoder output is sound.** Per-channel statistics of the dumps: VAG effects 44.1 kHz mono, peaks at 1.0, no discontinuities; AT9 dialogue 48 kHz mono, peaks 0.84-0.99, no discontinuities; AT9 stereo music both channels alike (RMS 0.08-0.20, no discontinuities). Nothing in the decoders needed changing.

**Dumps.** One file per voice and format now, appended across setups (`voice-<handle>-<rate>hz-<ch>ch-<codec>.wav`), so a retriggered effect shows every play and the 256-file cap is not spent on one-shots.

### 4.5 Risks

- Two Vulkan devices in one process (Agc's and Gnm's) is fine in phases 3.1 and 3.2 because no Agc title runs in the same process; it only matters if both drivers must coexist.
- The texture cache relies on faulting pages the CPU writes while the GPU reads. Native execution means the title's threads touch those pages directly; the protection changes must be process-wide and thread-safe, which shadPS4 already handles on Windows, but AnyPS5's `libc` also protects guest pages for its own tracking. Conflicting protections surface as spurious access violations and must be reconciled in phase 3.3.
- GCN shaders that shadPS4 patches at translation time (the `LdsDirect` operand noted for this title) come along with the recompiler; nothing extra is needed, but the shader cache must not be shared with shadPS4's.
- `sceGnmSubmitAndFlipCommandBuffers` and `sceGnmRequestFlipAndSubmitDone` write a flip label into the title's command buffer (`PatchFlipRequest` in shadPS4). The title's buffers live in direct memory it owns; writing into them is legitimate on native execution as well.
